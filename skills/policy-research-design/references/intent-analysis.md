# 의도 파악 — 요청 한 줄에서 목차까지

요청문에는 의도의 일부만 실린다. 사용자는 누가 읽는지, 왜 지금인지, 어디에 쓸지를 당연하게 여겨 적지 않는다. 설계자가 할 일은 그 빈자리를 그럴듯한 값으로 메우는 것이 아니다. **말해진 것·추론한 것·모르는 것을 갈라 놓고, 목차를 가르는 미상만 골라 묻는 것**이다.

## 막아야 할 실패 다섯

| 실패 | 모습 | 결과 |
|---|---|---|
| 문면 직역 | 주제 명사만 읽고 표준 목차를 채운다 | 어떤 요청이든 같은 보고서가 나온다 |
| 빈칸 메우기 | 모르는 독자·용도를 그럴듯하게 정해 놓고 사실처럼 쓴다 | 틀린 전제가 목차 전체에 퍼진다 |
| 과잉 해석 | 추론한 '진짜 의도'로 요청을 바꿔치기한다 | 시킨 것이 빠진 보고서가 나온다 |
| 의도 증발 | 1절에서 분석해 놓고 목차를 짤 때는 잊는다 | 의도분석과 목차가 따로 논다 |
| 의도 침식 | 게이트 지적을 받을 때마다 범위를 깎다가 쓰임을 잃는다 | 실행은 되는데 쓸 데가 없는 설계 |

**원칙 — 문면은 바닥, 용도는 방향타.** 요청문에 적힌 것은 빠짐없이 수행한다(바닥). 추론한 용도는 무엇을 두껍게·먼저·깊게 다룰지를 정한다(방향타). 방향타로 바닥을 뚫지 않는다 — 추론한 목적이 문면과 충돌하면 문면을 따르고, 충돌을 질문으로 올린다.

## 1. 원문을 읽는다

`_workspace/00_request.md`가 1차 입력이다. 사용자가 쓴 글자 그대로가 들어 있다.

- 스폰 프롬프트의 요약과 원문이 다르면 **원문이 우선**한다. 요약은 리더의 해석이다.
- 원장의 「리더 메모」 칸과 스폰 프롬프트에만 있는 정보는 〔추론〕의 단서로만 쓴다.
- 원장이 없으면 리더에게 요청한다. 받지 못하면 스폰 프롬프트에서 사용자 발언으로 인용된 부분만 원문으로 취급하고, 그 사실을 의도 확인서 첫 줄에 적는다.
- 원장 ⑤(이후 발언)에 답변·수정 지시가 추가돼 있으면 최초 요청과 함께 읽는다. 뒤의 발언이 앞의 것을 고친다.

**오독 사례를 읽는다.** `~/.claude/intent-misreads.md`가 있으면 원문 다음에 읽는다. 사용자가 지난번에 바로잡은 읽기가 한 건씩 쌓여 있다(요청 원문 · 설계자의 읽기 · 사용자의 정정 · 다음에 적용할 것).

- 같은 유형의 단서가 이번 요청에 있으면 〔추론〕의 **단서**로 쓴다. 단서 칸에 "오독 사례 2026-07-30 분량"처럼 적는다.
- 등급을 〔명시〕로 올리지 않는다. 지난번의 정정이 이번에도 맞는다는 보장은 없다. 사례가 가리키는 쪽을 기본 가정으로 삼되, 설계를 가르면 분기 질문으로 올린다.
- 파일이 없거나 닿는 사례가 없으면 건너뛴다.

## 2. 요구어를 전수 추출한다

요청문을 성분으로 쪼갠다. 주제 명사만 읽으면 모든 요청이 같은 보고서가 된다.

| 성분 | 읽는 법 |
|---|---|
| **동사** | 무엇을 해 달라는가 — 산출물의 유형을 정한다(아래 표) |
| **대상 명사구** | 무엇에 대해. 사용자가 고른 낱말을 그대로 적는다 |
| **수식·한정어** | "~중심으로" "~관점에서" "간단히" "설득력 있게" "~까지만" — 무게중심과 범위의 지시다 |
| **쓰임 단서** | "~에 보고" "~ 설득" "~ 제출용" "~ 회의 전까지" — 용도·독자·기한 |
| **계기 단서** | "~라는 지적이 있어서" "~가 바뀌면서" — 왜 지금인가 |
| **빠진 것** | 통상 있을 법한데 없는 것(대상·기간·독자) — 미상 후보 |

**동사가 산출물을 정한다.**

| 요청의 동사 | 사용자가 받고 싶은 것 | 목차의 무게중심 |
|---|---|---|
| 발굴·도출·찾아줘 | 후보 목록과 고른 이유 | 선별 장치(후보 풀 → 기준 → 압축) |
| 분석·진단 | 왜 그런가에 대한 설명 | 현황·원인 |
| 비교·벤치마킹 | 나란히 놓은 표와 차이의 의미 | 비교 축·비교표 |
| 검토·타당성 | 해도 되는가에 대한 판정 | 판정 기준·찬반 논거·성립 조건 |
| 평가·점검 | 한 것이 잘 됐는가 | 평가 기준·성과 자료 |
| 설계·방안·개편 | 바로 추진할 수 있는 안 | 대안 상세·실행 요건 |
| 대응·논리·설득 | 상대의 반론에 버틸 논거 | 쟁점별 논거·반론 대응 |
| 정리·동향·알아봐줘 | 빠짐없는 요약 | 분류 체계·망라성 |

추출한 요구어는 뒤에서 **설계의 어디에 반영됐는지 하나씩 대조**한다(§10 출력의 「요구어 대조」). 반영처가 없는 요구어는 누락이다.

## 3. 의도 8요소에 근거 등급을 붙인다

| 요소 | 묻는 것 |
|---|---|
| **용도** | 완성되면 어디에 쓰이는가(보고·제출·협의·발간·내부 검토) |
| **독자** | 누가 읽는가. 이미 무엇을 알고, 무엇을 믿고 있는가 |
| **결정·행동** | 이 문서가 떠받칠 결정은 무엇이고 선택지는 무엇인가 |
| **계기** | 왜 지금인가(예산 편성·법 개정·국정과제·감사·국회 지적·상급자 지시·사건) |
| **성공 기준** | 무엇이 담겨 있으면 사용자가 "이거다" 하는가 |
| **필수·금기** | 반드시 담을 것 / 건드리지 않을 것 |
| **입장** | 사용자가 이미 기울어 있는 결론·선호 대안 |
| **비범위** | 요청하지 않은 것, 다음으로 미룰 것 |

**등급 — 요소마다 하나를 단다.**

- 〔명시〕 원문이나 사용자 제공 자료에 글자 그대로 있다 → 해당 구절을 **인용**한다
- 〔추론〕 단서에서 끌어냈다 → **단서**를 적는다
- 〔미상〕 단서가 없다 → 비워 둔다. 그럴듯한 값을 넣지 않는다

**추론이 기댈 수 있는 단서:** ①요청문의 낱말 선택 ②첨부 자료(과업지시서·메모·기존 초안이 무엇에 지면을 썼는가) ③같은 대화의 앞선 발언 ④이전 실행의 결정(`_workspace_*/`) ⑤발주·소속 기관의 성격과 권한 ⑥시점(예산 주기·입법 일정).
"보통 이런 보고서는 이렇다"는 단서가 아니다. 그것이 표준 목차로 끌려가는 힘의 정체다.

**등급 규율:** 〔추론〕을 〔명시〕처럼 쓰지 않는다. 설계의 뒤 절(RQ·분석틀·목차)에서 추론 항목에 기대어 결정했으면 그 자리에 "(추론)"을 달고, 틀렸을 때 바뀌는 곳을 적는다.

## 4. 수단-목적 사다리를 두 칸 오른다

요청된 것은 대개 수단이다. "그래서 이것으로 무엇을 하려는가"를 두 번 묻는다.

> "해외사례 조사해 줘" → (무엇에 쓰려고?) 국내 제도 설계의 참고 → (그 설계는 어디에?) 내년 법 개정안의 근거 조항

올라간 칸마다 등급을 단다(대개 〔추론〕이나 〔미상〕). 사다리는 **무게중심을 정하는 데만** 쓴다. 위 예에서 사다리가 맞다면 사례를 나라별로 망라할 것이 아니라 조문화에 필요한 요소(적용 대상·요건·집행 주체)를 축으로 비교해야 한다. 그렇더라도 요청된 "해외사례 조사"는 그대로 수행한다.

## 5. 해석 후보를 세운다

요청을 읽는 방법 가운데 **서로 다른 목차를 낳는 것** 2~3개를 적는다.

| | 해석 A | 해석 B |
|---|---|---|
| 한 문장 | 〔누가〕 이것으로 〔무엇을〕 | … |
| 이 해석이면 목차는 | 무게중심·빠지는 장 | … |
| 지지 단서 | 원문 인용 | … |
| 반대 단서 | | |

- 후보들이 **같은 목차로 수렴하면** 그 모호성은 해가 없다. 묻지 않고 넘어간다.
- 목차가 갈리면 그 갈림목이 곧 분기 질문이다(§8).
- 단서가 가장 많은 후보를 채택하고 이유를 적는다. 버린 후보는 "이 해석이었다면 달라질 곳"으로 남긴다.

요청이 구체적이어서 다른 해석이 서지 않으면 "해석 후보 없음 — 단일 해석"이라 쓰고 근거 한 줄을 붙인다. 억지로 만들지 않는다.

## 6. 의도 한 문장을 쓴다

> **이 보고서를 받은 〔독자〕가 이것으로 〔결정·행동〕을 할 수 있어야 한다.**

주제문 말고 쓰임문으로 쓴다.

- 약함: "청년 주거 정책을 종합적으로 분석한다"
- 좋음: "주거정책과장이 내년 예산 요구에서 월세 지원과 공공임대 중 어느 쪽에 증액을 걸지 정할 수 있어야 한다"

〔미상〕이 섞여 문장이 서지 않으면 그것이 확신도 '낮음'의 신호다(§9). 빈칸을 그대로 둔 문장을 쓴다.

## 7. 어긋남 시나리오를 쓴다

완성본을 받은 사용자가 "이게 아닌데"라고 말한다면 가장 그럴듯한 이유 세 가지를 적고, 각각을 **목차의 어디서 막는지** 적는다.

자주 나오는 유형:
- 범위가 넓어 깊이가 없다
- 독자가 이미 아는 현황에 지면을 다 썼다
- 대안이 원론이라 그대로 쓸 수 없다
- 제언이 사용자 조직의 권한 밖이다
- 요청한 관점("~중심으로")이 한 절로 쪼그라들었다
- 독자가 반대할 지점에 대한 대비가 없다
- 사용자가 고른 낱말을 다른 개념으로 바꿔 썼다

### 수용 기준 — 초안을 판정할 문장을 미리 적는다

의도 한 문장은 방향을 잡아 주지만 그것만으로는 초안을 판정할 수 없다. 의도를 잘 읽고도 결과를 판정할 수단이 없으면 "의도를 수행했는가"는 감상으로 남는다. 설계 단계에서 **수용 기준 3~5개**를 적는다.

- 의도 한 문장, 필수 항목, 어긋남 시나리오에서 뽑는다.
- 초안을 펼쳐 놓고 **예/아니오로 답할 수 있게** 쓴다.
  - 약함: "반론에 충분히 대응한다"
  - 좋음: "예상 반론마다 답하는 절이 있고, 답마다 해외 근거가 한 건 이상 붙어 있다"
- 번호를 붙인다(A1, A2 …). 검토관이 초안 검수에서 기준별로 판정하고, 리더가 최종 보고에 기준별 결과를 적는다.
- 목차 승인 때 사용자가 함께 본다. 에이전트는 주어진 기준을 향해 달리므로 기준이 틀리면 초안도 틀린 곳으로 간다.
- **기준은 결과물을 보면서 다듬어진다.** 초안을 본 사용자가 "이게 아닌데"라고 하면 빠져 있던 기준이 그 말에서 드러난 것이다. 원장 ⑤에 원문으로 적고 수용 기준에 추가한다. 기존 기준은 지우지 않고 개정 표시를 단다.

## 8. 분기 질문만 묻는다

**질문 자격 — 답에 따라 목차(장 구성·무게중심·RQ)가 달라지는가.** 달라지지 않으면 질문이 아니라 가정이다. 가정 목록에 적고 진행한다.

```
Q1. '효과가 없다'는 지적을 받아들이고 개편안을 내는 연구입니까, 지적의 타당성부터 따지는 연구입니까?
  · 기본 가정: 개편안 (근거: 원문 "손보려고 합니다")
  · 답이 다르면: 4장이 대안 설계 → 효과 점검으로 바뀌고 RQ1이 "효과가 있었는가"가 된다
```

- **최대 3개**(브리프는 2개). 넘치면 목차를 가장 크게 바꾸는 순으로 남긴다.
- 선택지형으로 묻는다. 사용자가 한 번에 답할 수 있어야 한다.
- **상한은 목표가 아니다.** 설계를 가르는 질문이 하나뿐이면 하나만 낸다. 개수를 채우려고 가정으로 충분한 것을 질문으로 올리지 않는다(회귀 실행 11건 중 10건이 상한을 꽉 채웠다).
- 한 질문에 물음 하나. 여러 물음을 한 번호로 묶어 개수를 맞추지 않는다(실측에서 반복 관측). 딸린 물음은 가정으로 내리거나 ★ 가정으로 적는다.
- 묻기 전에 원문을 다시 읽는다. 요청문·자료에 답이 있는 것을 묻지 않는다.
- 모든 질문에 **기본 가정**을 단다. 답이 없어도 파이프라인은 그 가정으로 진행한다.

**가정 사항에도 무게가 있다.** 목차는 안 바꾸지만 **틀리면 결론이나 핵심 수치가 바뀌는 가정**에는 ★를 단다(추계의 기준 연도, 대상 집단의 정의, 내부 자료 확보 여부 등). 리더는 목차 승인 때 ★ 가정을 분기 질문 바로 뒤에 보인다. 질문 수를 줄이는 것이 목적이지 불확실성을 감추는 것이 목적이 아니다.

**이 구분이 맡긴 범위다.** 무엇을 팀이 정하고 무엇을 사용자가 정하는지를 섞지 않는다.

| 항목 | 누가 정하는가 |
|---|---|
| 가정 | 팀이 정하고 목록에 남긴다 |
| ★ 가정 | 팀이 정하되 목차 승인 때 먼저 보인다 |
| 분기 질문 · 확인할 전제 | 사용자가 정한다. 답이 없으면 기본 가정으로 가되 그 사실을 적는다 |
| 필수 · 금기 | 팀이 바꾸지 못한다 |

**요청문의 전제를 점검한다.** 요청문이 깔고 있는 사실관계(일정·제도 명칭·기관 권한·수치)가 설계자가 아는 것과 어긋나 보이면 **「확인할 전제」**로 따로 적는다. 예: 요청문이 "올해 시행된 ○○법의 효과"를 묻는데 설계자가 아는 한 그 법은 아직 국회에 계류 중이다 → 시행됐다면 효과 점검 연구이고, 계류 중이면 입법 지원 연구다. 요청문에 적힌 날짜·기한도 같은 방식으로 본다 — 그 시점에 그 절차가 실제로 열리는지를 행정 일정에 비춰 본다. 설계자가 고쳐 읽지 않는다. 어긋남을 적고 사용자가 답하게 한다. 설계자의 지식이 틀렸을 수도 있으므로 "확인 필요"로 쓴다. 전제가 틀리면 목차가 바뀌는 경우는 분기 질문으로 올린다.

## 9. 확신도를 판정한다

| 확신도 | 조건 | 설계자의 산출 | 리더의 조치 |
|---|---|---|---|
| **높음** | 용도·독자·결정이 〔명시〕이거나 단서가 겹치는 〔추론〕이고, 해석 후보가 한 목차로 수렴 | 설계 전체 | 게이트 진행. 분기 질문은 목차 승인 때 함께 제시 |
| **낮음** | 셋 중 하나 이상이 〔미상〕이고 해석 후보가 목차를 가른다 | 설계 전체(채택 해석 기준 **잠정안**) + 확신도 '낮음' 표시 | **검토관 게이트 전에** 사용자에게 의도 확인서·분기 질문을 먼저 제시 |

어느 쪽이든 설계는 끝까지 낸다. 답을 못 받아도 파이프라인이 멈추지 않게 하기 위해서다.

**확신도는 자기 평가다.** 자기 결과를 스스로 평가하면 후한 쪽으로 기운다(실측: 같은 요청을 두 번 돌렸더니 '높음'과 '낮음'이 갈렸다). 그래서 검토관이 설계 문서를 열기 전에 원문만 읽고 의도 한 문장을 따로 쓴다. 두 문장이 독자·결정·무게중심에서 갈리면 검토관이 확신도를 '낮음'으로 내린다.

## 9-1. 요청이 분명하면 가볍게 한다

용도·독자·결정이 모두 〔명시〕이고 다른 해석이 서지 않으면 **수단-목적 사다리(§4)와 해석 후보(§5)를 생략**하고 어긋남 시나리오는 1개만 쓴다. 요구어 대조, 등급 표, 수용 기준, 확인할 전제는 생략하지 않는다.

이 절차의 부품은 맨 위 표의 실패를 막으려고 있는 것이다. 채워야 할 칸이 아니다. 실측에서 구판 설계자도 원문을 그대로 받으면 의도를 읽어냈고, 신판은 소요 시간이 25~70% 늘었다. 값을 한 부품은 원문 인용 등급·요구어 대조·분기 질문 선별·전제 점검이었다. 모델이 나아져 어떤 부품이 더는 차이를 만들지 않으면 걷어낸다.

## 9-2. 답을 기다리는 동안 멈추지 않는다

분기 질문을 던지면 사용자의 답이 올 때까지 시간이 빈다. 그 시간에 **어느 답이 와도 버려지지 않는 일**을 먼저 한다.

- 조사 항목마다 범위를 단다. **〔공통〕** — 어느 해석을 택하든, 분기 질문에 어떤 답이 오든 쓰이는 근거. **〔갈림: Q2〕** — 채택 해석이나 특정 분기 답에 딸린 근거(어느 질문에 딸렸는지 적는다).
- 리더는 답을 기다리는 동안 〔공통〕 항목만 먼저 맡길 수 있다. 〔갈림〕 조사와 집필은 사용자의 답과 승인을 받은 뒤에 한다.
- 확신이 서지 않는 항목은 〔갈림〕으로 둔다. 〔공통〕이라 적었는데 답에 따라 버려지면 그 조사는 낭비다.
- 확신도가 낮을수록 〔공통〕 항목부터 조사 순서를 잡는다. 「확인할 전제」를 풀어 줄 근거(제도 현황·일정·법령 원문)는 대개 〔공통〕이고, 그 조사 결과가 분기 질문의 답을 대신해 주기도 한다.

## 10. 의도에서 목차로

**① 무게중심 — 분량은 의도가 배분한다.** 의도 한 문장이 요구하는 일에 가장 많은 지면을 준다. 표준 목차의 장별 기본 배분을 그대로 쓰지 않는다.

**② 용도가 목차의 형태를 정한다.**

| 용도 | 두껍게 | 얇게 | 유의 |
|---|---|---|---|
| 결정 지원(대안 중 선택) | 대안 비교·판정 기준 | 일반 현황 | 사용자가 이미 쥔 선택지가 있으면 그것이 대안이다 |
| 정당화·설득(방침은 섰다) | 필요성 근거·반론 대응·소요 재원 | 대안 나열 | 결론이 기운 설계다. 반증 조건을 명시한다 |
| 탐색·의제 발굴 | 후보 풀·선별 장치 | 실행 로드맵 | 선별 기준부터 승인받는다 |
| 제도 설계(어떻게 할 것인가) | 설계 요소·실행 요건·해외 제도의 구조 | 필요성 논증 | 법·예산·조직 실현성 |
| 평가·점검 | 평가 기준·성과 자료 | 해외 동향 | 논리모형 |
| 대응 논리(지적·질의에 답) | 쟁점별 사실관계·논거 | 이론적 배경 | 쟁점 목록이 곧 목차다 |
| 현황 파악·동향 | 분류 체계·망라 | 정책 대안 | 제언은 시사점 수준 |

**③ 의도-목차 대응표를 양방향으로 만든다.**

- **의도 → 목차:** 의도 요소(결정·필수 포함·요구어)마다 그것을 수행하는 장·절을 적는다. 대응 장이 없으면 누락이다.
- **목차 → 의도:** 장마다 "이 장이 없으면 의도의 무엇이 빠지는가"를 적는다. 답이 "표준 구조라서"뿐이면 **관성 장**이다. 빼거나, 절로 줄이거나, 남기는 근거를 적는다. 발주처 양식이 강제하는 장은 "양식 요건"이라 적고 분량만 최소로 잡는다.

**④ 장 제목은 사용자의 낱말로 쓴다.** 사용자가 '재고용'이라 했으면 '계속고용'으로 바꾸지 않는다. 바꿔야 하면 이유를 적고 분기 질문 후보로 올린다.

## 11. 설계를 고칠 때 의도를 지킨다

게이트 지적이나 근거 미확보로 RQ를 낮추거나 장을 덜 때마다 묻는다 — **고친 뒤에도 의도 한 문장이 수행되는가.**

- 수행되면 그대로 고친다.
- 수행되지 않거나 약해지면 조용히 낮추지 않는다. 의도 확인서의 **「의도 대비 달라진 점」**에 "무엇을 낮췄고, 그래서 사용자가 못 하게 된 일이 무엇인지"를 적는다. 리더가 목차 승인 때 사용자에게 보인다.

실행 가능성 때문에 쓰임을 깎을지는 사용자가 정한다. 설계자와 검토관이 대신 정하지 않는다.

**브리프 모드 경량판:** 요청 원문 · 의도 한 문장 · 확신도 · 요소 표는 **용도·독자·결정 3행** · 요구어 대조 · 어긋남 시나리오 1개 · 수용 기준 2~3개 · 분기 질문 2개 이내. 해석 후보는 목차가 갈릴 때만 쓴다. 대응표는 압축 목차 4절에 "의도 연결" 열을 하나 더하는 것으로 갈음한다.

## 예시 (합성)

**요청 원문**
> 도 차원에서 청년 농업인 정착 지원을 손보려고 합니다. 도의회 업무보고가 11월이라 그 전에 정책연구보고서로 정리해 주세요. 기존 지원금 방식이 효과가 없다는 지적이 있어서요.

**요구어 추출** — 동사 "손보려고"(개편) · "정리해"(보고서화) / 대상 "청년 농업인 정착 지원" / 한정 "도 차원에서" / 쓰임 "도의회 업무보고" "11월 … 전에" / 계기 "기존 지원금 방식이 효과가 없다는 지적"

| 요소 | 내용 | 등급 | 인용 또는 단서 |
|---|---|---|---|
| 용도 | 도의회 업무보고 자료의 근거 | 〔명시〕 | "도의회 업무보고가 11월이라" |
| 독자 | 도의원, 담당 국·과 | 〔추론〕 | 단서: 업무보고의 청중 |
| 결정·행동 | 지원금 방식의 유지·보완·전환 중 선택 | 〔추론〕 | 단서: "손보려고" + "지원금 방식이 효과가 없다는 지적" |
| 계기 | 지원금 방식 효과에 대한 지적 | 〔명시〕 | "효과가 없다는 지적이 있어서요" — 지적의 주체는 〔미상〕 |
| 성공 기준 | | 〔미상〕 | — |
| 필수·금기 | 도 권한 안의 수단 | 〔추론〕 | 단서: "도 차원에서" |
| 입장 | 개편 쪽으로 기울어 있음 | 〔추론〕 | 단서: "손보려고" |
| 비범위 | 국가 사업 개편 | 〔추론〕 | 단서: "도 차원에서" |

**해석 후보**

| | A. 개편안 설계 (채택) | B. 지적에 대한 대응 논리 |
|---|---|---|
| 한 문장 | 담당 과가 업무보고에서 지원 방식 개편안을 제시할 수 있어야 한다 | 담당 과가 업무보고에서 '효과 없다'는 지적에 사실관계로 답할 수 있어야 한다 |
| 목차 | 대안 설계·비교가 중심, 효과 점검은 진단 한 절 | 효과 점검이 중심, 대안은 보완책 수준 |
| 지지 단서 | "손보려고 합니다" | "지적이 있어서요" — 지적이 계기라는 점 |

**분기 질문**
```
Q1. '효과가 없다'는 지적을 받아들이고 개편안을 내는 연구입니까, 지적의 타당성부터 따지는 연구입니까?
  · 기본 가정: 개편안 (근거: "손보려고 합니다")
  · 답이 다르면: 4장이 대안 설계 → 효과 점검으로 바뀌고 RQ1이 "지원금은 효과가 있었는가"가 된다
```

**가정 사항(묻지 않음)** — 분석 기간 최근 5년 · 비교 대상은 타 시·도. 어느 쪽으로 정해도 목차가 같다.

**의도 한 문장** — 도 담당 과가 11월 도의회 업무보고에서 청년 농업인 지원 방식을 어떻게 바꿀지 근거와 함께 제시할 수 있어야 한다. **확신도 낮음** — 결정이 〔추론〕이고 해석 A·B가 4장을 가른다.

**수용 기준**
- A1. 현행 지원금 방식의 효과에 대한 판정이 한 절에 있고, 판정의 근거 자료가 명시돼 있다
- A2. 비교한 대안이 모두 도의 예산·조례로 실행할 수 있는 수단이다
- A3. 권고안에 소요 재원과 시행 시점이 적혀 있다
- A4. 업무보고에 그대로 옮길 수 있는 요약이 맨 앞 한 쪽에 있다

**목차에 미친 영향** — 표준 목차의 '이론적 배경'·'해외 동향'은 관성 장으로 판정. 도의원이 읽을 보고서에서 격차 이론은 쓰임이 없어 1장의 한 절로 줄이고, 해외 대신 "도 차원에서"에 맞춰 **타 시·도 사례**로 바꿨다. 지면은 4장(지원 방식 대안 비교)과 5장(도 예산·조례로 실행할 수 있는 요건)에 몰았다.
