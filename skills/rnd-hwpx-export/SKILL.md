# 문서 HWPX 변환

승인된 본문을 발주처가 요구하는 양식의 .hwpx로 정확히 옮긴다. 내용을 새로 쓰거나 요약하지 않는다 — 형식 변환과 양식 준수에만 집중한다.

> **의존성**: 이 스킬의 변환 경로는 kordoc MCP(제3자 오픈소스, `npx kordoc@latest mcp`)에 의존한다. 미설치 시 마크다운/docx 산출을 대안으로 제시한다(아래 에러 대응).

## 왜 양식이 중요한가
정부 R&D 제안서·정책보고서는 발주처 지정 양식 준수가 평가 자격 요건인 경우가 많다. 양식을 벗어나면 내용이 좋아도 감점·반려될 수 있다. 따라서 지정 양식이 있으면 반드시 그 양식을 기준으로 채운다.

## 절차

### 1. 입력 확인
- 승인된 본문: 오케스트레이터가 지정한 초안 파일 (예: `_workspace/04_proposal.md`, `_workspace/04_report_draft.md`)
- 지정 양식 유무: `_workspace/00_input/`에 발주처 양식(.hwp/.hwpx/.docx)이 있는지 확인
- 양식 제약: RFP/설계 분석 산출물의 글꼴·여백·분량 정보

### 2. 양식 분기

**(A) 지정 양식이 있는 경우 — 폼 채우기 방식**
1. `mcp__kordoc__detect_format`으로 형식 확인
2. `mcp__kordoc__parse_form`으로 양식의 채울 항목(필드/표/섹션)을 파악
3. 초안 본문을 양식의 각 항목에 매핑 (섹션 제목 기준으로 대응)
4. `mcp__kordoc__fill_form`으로 양식에 내용을 채워 .hwpx 생성

**(A-2) 사용자가 한글에서 편집한 hwpx를 기준으로 다시 만들 때**

사용자는 앞 몇 쪽을 직접 고치고 메모를 달아 돌려준다. 그 파일이 **기준본**이다.
1. 사용자의 최신 저장본을 원본(SRC)으로 삼는다. 작업 폴더의 옛 md·옛 빌드본에서 출발하지 않는다.
2. 직전 빌드본과 본문을 문단 단위로 대조해 사용자 편집(삭제·추가·서식 변경)을 목록으로 뽑는다 — 재빌드 전에 "유실 0"을 먼저 확인한다. 사용자가 지운 표·그림·문장은 되살리지 않는다.
3. 사용자가 손댄 구간의 XML은 그대로 두고 나머지만 원고에서 다시 만든다. 다시 만드는 구간은 **사용자 구간의 문단·글자 모양 id를 그대로 참조**한다(사용자 편집 > 참고양식 규칙 > 하우스 스타일).
4. 사용자가 저장한 문단은 `hp:linesegarray`(조판 캐시)를 지워야 새 문단 모양이 렌더에 반영된다.
5. 한글 메모는 `hp:fieldBegin type="MEMO"`로 저장되고 중첩 문단이 있어 정규식 분할이 어긋난다 — XML 파서로 최상위 문단을 세고 메모를 전수 추출한다.
6. 출력은 새 판 이름(`…_초안N+1_YYMMDD.hwpx`)으로. 사용자 파일을 덮어쓰지 않고, 같은 이름으로 두 번 보내지 않는다.

**(B) 지정 양식·샘플이 모두 없는 경우 — 표준 생성 방식**
1. `mcp__kordoc__generate_document`로 변환한다 — GFM 표→정부 서식 표, 개조식 부호(□/ㅇ/-)→리스트 깊이 매핑을 지원하므로 표가 있는 원고도 그대로 처리된다.
2. **팀 문서 삽입용 모듈**은 표지·목차·쪽번호 off + `h2_marker=none`(섹션 제목 문자 유지) + 휴먼명조로 생성한다.
3. 기관 고유 스타일이 필요하면 사용자가 제공한 클린 템플릿 또는 직전에 생성한 hwpx를 스타일 공여자로 재사용한다(독점 양식 파일을 저장소에 두지 않는다 — 런타임에 사용자가 제공).
4. RFP/설계 분석의 글꼴·여백 제약을 반영한다.

### 2.5 변환 전 전처리 + 샘플 선검증
- 원고를 변환용 파일(`04b_for_hwpx.md` 등)로 전처리한다: 작업 메타·말미 메모 제거, 3레벨 리터럴 "- "를 "·"로 치환(마크다운 리스트 오인 방지), □/○ 글머리·GFM 표는 보존. **전처리본은 지우지 않고 `_workspace/`에 남긴다** — 변환 검증의 기준이 승인 초안이 아니라 이 파일이기 때문이다. 전처리에서 걷어내는 것은 작업 메타(안내 인용문·추적 태그·자기점검 메모)뿐이며 본문 문장·수치·`[보강 필요]` 표시는 건드리지 않는다. 걷어낸 항목은 변환 보고에 적는다.
- **단독행 날짜(`YYYY. M. D.`)는 순서목록으로 오파싱**(`2026. 8. 31.` → `□ 8. 31.`)되므로 변환 전 원고 차원에서 제거·문장 편입한다(이스케이프 우회보다 근본 제거 우선).
- 본 변환 전 **소형 샘플로 (1) 도구 작동 (2) 표·부호·제목 렌더링을 선검증**한 뒤 전체를 변환한다.

### 3. 변환 시 보존 원칙
- 본문 텍스트는 작성가/검수관이 확정한 그대로 옮긴다
- 마크다운 표는 hwpx 표로 변환한다 (목표체계도, 일정표, 역할분담표 등)
- 형식상 불가피한 조정(셀 분할, 줄바꿈)은 변환 보고에 명시한다

### 4. 검증 — 스크립트로 판정한다
"검증했다"는 말이 아니라 **종료 코드**로 통과를 정한다. 이 스킬에 동봉된 검증기를 변환에 넣은 원고와 결과 파일에 돌린다:

```
python3 <이 스킬 디렉토리>/scripts/verify_hwpx.py _workspace/04b_for_hwpx.md _workspace/06_report.hwpx
```

| 종료 코드 | 뜻 | 다음 |
|---|---|---|
| 0 | 통과 | 출력 전문을 변환 보고에 붙인다 |
| 1 | 불합격 | 출력이 짚은 대목을 고쳐 재변환 → 재실행. 같은 불합격이 되풀이되면 리더에게 상위 모델 재스폰을 요청 |
| 2 | 실행 오류(파일 없음 등) | 경로를 바로잡아 재실행. 통과로 치지 않는다 |

검증기가 보는 것: ①패키지 무결성(zip·mimetype·필수 엔트리·XML 정형성) ②표 대조(원고의 표마다 행·열 수가 같은 표가 같은 순서로 있는가) ③본문 대조율(기준 99.5%, 통째로 사라진 대목은 1건이어도 불합격) ④수치 보존(원고의 숫자가 같은 횟수 이상 있는가) ⑤마크다운 잔재(`**`·`|---`). 남아 있는 `[보강 필요]` 표시도 세어 준다.

- **변환가의 실행과 별개로 리더가 같은 명령을 한 번 더 돌린다.** 변환가의 보고가 아니라 리더가 본 종료 코드가 통과 판정이다.
- 기준은 변환에 실제로 넣은 파일(전처리본)이다. 승인 초안을 기준으로 주면 전처리에서 걷어낸 작업 메타 때문에 불합격이 난다.
- 지정 양식 채우기 경로(A)는 양식 자체의 표가 섞이므로 `--no-tables`로 돌리고, 표는 `mcp__kordoc__parse_table`로 따로 확인한다.
- 검증기가 못 보는 것: 쪽수·글꼴·여백. `mcp__kordoc__parse_document` 재파싱과 한글에서의 육안 확인으로 보완한다.
- **"PASS"는 항목마다 실측값과 함께 보고한다** — 본문 글자수(원고 대비 %), 표·그림 수(원고 : 산출), 본문 pt·줄간격·여백(양식값과 대조), 직전 판 대비 파일 크기(급감이면 경고), 패키지 필수 파일, 근사 렌더 쪽수(`mcp__kordoc__render_document`). 실측 오보고 사례: 본문 15pt·줄간격 180%로 조판하고 "원고 50% 삭제 필요"로 보고, 편집 주석 3,300자가 섞인 자체 병합본 사용, 빈 파일을 "전 항목 PASS"로 보고. 값 없는 PASS는 리더가 인정하지 않는다.
- python3가 없는 환경이면 같은 항목(표 행수 1:1, 본문 왕복 대조, zip·mimetype)을 `parse_document` 재파싱으로 직접 세어 수치로 보고하고, "스크립트 미실행"이라고 적는다.

문제가 있으면 보완 후 재생성한다. 표 데이터 이상이 의심되면 `mcp__kordoc__parse_table`로 특정 표를 직접 검사해 손실 지점(생성 vs 이후 단계)을 격리한다.

**스위트 통과는 "정상"이 아니다 — 반드시 렌더해서 눈으로 봐라.** 스위트는 참조 정합·행렬 수·왕복 자수를 세지 **겹침·잘림·빈칸은 세지 않는다.** 실측에서 14항목을 전부 통과한 산출물이 화면에서는 한 줄이 다른 줄 **위에 겹쳐 찍혀** 있었다(조판 캐시가 원본 위치를 물고 있었다). `mcp__kordoc__render_document`로 렌더해 확인한다.

- **개수로만 확인하지 마라.** "표 44개 중 39개 보존(88.6%)"을 적어 놓고 결론을 "누락 없음"으로 쓰는 자기모순이 실측에서 나왔다. 스위트의 각 수치가 **1:1인지**를 보고, 어긋나면 어긋난 채로 보고한다.
- **이상해 보이면 공여자/양식 원본을 같은 렌더러로 렌더해 대조하라.** 렌더러 자체의 한계(쪽나눔 미구현 등)를 우리 결함으로 오인하지 않기 위해서다. 실측에서 '상자 잘림'이 원본에서도 동일하게 나타나 오탐으로 판명됐다.
- **조판 캐시는 지우지 말고 옮겨라.** 캐시(`linesegarray`)는 글자가 아니라 위치·폭을 담는다. 그대로 두고 줄을 복제하면 겹치고, 지우면 캐시를 신뢰하는 렌더러에서 **글상자 글자가 통째로 사라진다**. 기존 줄 간격을 읽어 복제분에 누적 적용하는 것이 답이다.

### 5. 분량·양식 점검
RFP/설계 분석의 페이지 한도·분량 제약을 확인한다. 초과 시 리더와 작성가에게 경고한다 (임의로 본문을 잘라내지 않는다).

## 기존 hwpx 직접 편집 (재생성 없이 고치기)

이미 완성된 hwpx의 **내용 일부만 고치거나 서식만 바꿀 때**는 재생성하지 않는다. 재생성은 사용자가 한글에서 손본 편집·이미지·표 서식을 전부 날린다. hwpx는 zip+XML이므로 `Contents/section0.xml`(본문)과 `Contents/header.xml`(글자·문단 속성)을 직접 손보는 편이 안전하고 정확하다.

**텍스트 편집의 급소 — `<hp:t>`는 잘려 있다.** 한 문장이 서식 경계마다 여러 `<hp:run>/<hp:t>`로 쪼개져 있어, 노드 하나씩 문자열 치환하면 문장을 가로지르는 패턴이 안 잡힌다. 반드시 **문단 단위로 텍스트를 이어붙여 좌표(start, end)를 계산한 뒤 각 t 노드에 되돌려 쓴다.**

**표 셀은 그 자체가 `hp:p`다.** 문단을 순회할 때 중첩 `hp:tbl` 안의 `hp:t`를 제외하지 않으면, 표를 담은 문단에서 셀들의 텍스트가 하나로 이어붙어 **셀 경계를 넘는 오탐**이 생긴다. 각 문단은 "자기 소유 t 노드"만 보게 하고, 셀은 별도 단위로 처리한다.

**괄호는 중첩까지 본다.** `\(([^()]*)\)` 정규식은 안에 괄호가 든 경우를 놓친다. 균형 스캐너로 최외곽 쌍을 잡아야 전수 조사가 성립한다.

**조판 캐시(`linesegarray`)를 지운다.** 텍스트 길이를 바꿨으면 남아 있는 줄 배치 캐시가 어긋난다. 전부 제거하면 한글이 열 때 재계산한다. 지우지 않으면 렌더러가 **옛 배치를 그대로 보여줘 검증이 무의미해진다**(편집 전후 페이지 수가 똑같이 나오면 이걸 의심하라).

**편집 스크립트의 3대 안전장치**
1. **사전 매칭 검사** — 각 구(舊)문자열이 문서에 정확히 1회 등장하는지 먼저 확인하고, 아니면 **한 글자도 고치지 말고 중단**한다. 엉뚱한 위치를 고치는 사고가 가장 비싸다.
2. **불변식 검증** — 편집 후 표 개수·표별 행수 1:1, zip 무결성, 미정의 charPr/paraPr 참조 0건을 확인한다. 내용 무관 편집(서식만)이면 본문 텍스트 완전 일치도 확인한다.
3. **재실행 가드** — 서식 적용 스크립트는 그 문서의 charPr 번호에 묶여 있다. 한글이 다시 저장하면 속성이 통합·재번호되어 **같은 번호가 다른 서식을 뜻하게 된다.** 이미 적용된 문서를 감지하면 스스로 중단하게 만든다.

**렌더 검증의 한계.** kordoc `render_document`의 reflow 엔진은 **쪽나눔(`pageBreak`·`pageBreakBefore`)을 구현하지 않는다.** "장은 페이지를 바꾸어 시작" 같은 요건은 렌더로 확인할 수 없다 — 파일의 속성값으로 확인하고, 최종 확인은 한글에서 한다.

**동시 편집을 전제하라.** 사용자는 작업 중에도 한글에서 같은 파일을 열어 저장한다. 매 작업 **시작 전에** 파일 크기·수정시각·본문 해시가 직전에 내가 쓴 것과 같은지 확인한다. 달라졌으면 **현재 파일을 기준으로 다시 시작**하고, 사용자에게 외부 변경을 알린다. 덮어쓰기 전 백업은 `_workspace/backup_<대상>_<작업>전.hwpx`로 남긴다.

**문단·그림 추가**
- **문단 추가** — 새 `hp:p`를 만들 때 같은 위계의 **견본 문단**(□ 줄이면 기존 □ 줄, - 줄이면 기존 - 줄)의 `paraPrIDRef`와 첫 run의 `charPrIDRef`를 그대로 쓴다. 앵커 문단은 본문 글자로 찾되 정확히 1회 등장하는지 먼저 확인한다(안전장치 1).
- **그림 교체** — 새 이미지를 **원본과 같은 픽셀 크기**로 렌더해 `BinData/` 안의 바이트만 바꾼다. 그림 개체(`hp:pic`)의 크기·위치를 건드리지 않아도 되므로 가장 안전하다.
- **그림 추가** — 기존 그림 문단을 통째로 복제해 `binaryItemIDRef`를 새 BinData id로, 개체 `id`·`instid`를 문서에 없는 값으로 바꾼다. `BinData/<새 id>.png`를 넣고 `Contents/content.hpf`에 `<opf:item id=… href="BinData/…" media-type="image/png" isEmbeded="1"/>`를 더한다 — 이미지·manifest·`hp:pic` 셋이 맞아야 그림이 뜬다.
- **이전 개정 표시 걷기** — 기준본에 이전 개정의 파란 글자가 남아 있으면 그 글자 속성(`header.xml`의 `textColor="#0000FF"`)을 검정으로 되돌린다. 서식 고유의 파란 안내문 속성은 이전 판과 대조해 가려내 그대로 둔다.

**파일명 길이.** macOS는 파일명을 **NFD(자모 분해)**로 세어 255바이트로 제한한다. 한글 한 글자가 자모 2~3개 × 3바이트 = 6~9바이트다. 긴 한글 과제명에 접미사를 붙이다 조용히 실패하므로, 저장 전에 NFD 바이트 길이를 계산해 확인한다.

## 배포·삽입 (팀 .hwp에 넣을 때)
- **hwpx→.hwp 복사·붙여넣기 시 표 본문 행이 소실**될 수 있다(헤더만 남는 표 스텁). hwpx 자체는 정상이므로(`parse_table`로 확인) 손실 지점은 복붙 단계다.
- **표의 이관은 HTML 병행 출력으로 우회한다**: 표 전체를 캡션과 함께 HTML(+열람용 MD)로 추출 → 브라우저에서 드래그·복사 → 한글에 붙여넣으면 실제 표로 보존된다. 개조식 텍스트는 복붙 손실이 없다. 마크다운 원문을 한글에 직접 붙이면 텍스트로 들어가므로 HTML 쪽을 안내한다.
- **팀 .hwp 원본은 절대 재생성하지 않는다**(이미지·타 모듈 서식 파괴). 스탠드얼론 hwpx + 한글 교체 표준절차(백업→구간 삭제→붙여넣기→그림 재배치→저장) 가이드 md를 동봉한다.
- **산출물+가이드 쌍 원칙**: 도구가 못 하는 마지막 수동 구간(한글 삽입·그림 배치)은 절차서 md로 메운다.

## 출력
- 최종: 사용자 지정 경로의 `<과제명>_<문서유형>.hwpx` (미지정 시 작업 디렉토리)
- 사본: `_workspace/`의 오케스트레이터 지정 경로 (예: `06_proposal.hwpx`, `06_report.hwpx`)
- 팀 삽입 시: 표 HTML(+MD)·교체 가이드 md 동봉
- 변환 보고: 매핑 결과, 전처리에서 걷어낸 항목, `verify_hwpx.py` 출력 전문(종료 코드 포함), 형식 조정 사항, 분량 점검 결과를 응답에 요약

## 에러 대응
- 양식 파싱 실패: 1회 재시도 → 실패 시 (B) 표준 생성으로 전환, "지정 양식 적용 실패 — 표준 양식 생성, 수동 확인 권장" 안내
- 본문 누락 발견: 누락 구간 보완 후 재생성
- 의존성 오류(kordoc/lxml 등): 에러를 명확히 보고하고 마크다운 산출물 유지를 대안으로 제시 (docx 변환이 가능하면 docx 폴백도 제시)
- kordoc MCP 호출이 차단된 경우(도구 게이트 장애 등): Bash에서 kordoc 엔진을 스크립트로 직접 구동해 우회 생성한다(`npx -y kordoc@latest` 계열, 임시 스크립트 방식 — 검증된 우회). 입력 파일을 먼저 완성해 두고 소형 프로브로 복구를 확인한 뒤 일괄 실행한다.

## 주의
- **kordoc generate는 숫자·'등' 앞 등에 줄바꿈 없는 공백(`<hp:nbSpace/>`)을 넣는다.** 한글에서는 공백으로 보이지만 다른 도구로 옮기거나 텍스트를 뽑으면 "탄력성0.17"·"연도등"처럼 붙는다(실측: 보고서 한 건에 43곳). 배포·전달본은 `<hp:nbSpace/>`를 일반 공백으로 바꾼다.
- 리더가 지정한 원고 파일만 입력으로 쓴다. 스스로 다른 판을 병합하지 않는다.
- 미승인 초안은 변환하지 않는다. 검수관(reviewer)의 승인 신호를 받은 뒤 시작한다.
- 내용 품질은 앞 단계가 책임진다. 변환가의 책임은 "제출 가능한 형식"이다.
